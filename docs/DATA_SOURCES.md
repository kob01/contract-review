# 数据来源、核验流程与免责边界

这份文档解释的不是"怎么跑代码"，而是**为什么这套系统的输出可以被信任到什么程度**。
法律 AI 的风险不在模型不够聪明，而在检索到的依据本身就是假的。

## 1. 系统内置了什么

| 内容 | 是否内置 | 说明 |
| --- | --- | --- |
| 合规红线规则（22 条） | ✅ | 阈值口径 + 判定逻辑 + 改写建议，均为**规则文本**，不是法条原文 |
| 法条原文 | ❌ **不内置** | 只登记"法规名 + 条号"的占位条目（`is_sample=True`） |
| 监管罚单 | ❌ | 需通过接口导入或采集后人工核对 |
| 演示合同样本 | ✅ | `samples/consumer-loan-demo.txt`，纯虚构 |

内置红线引用的依据线索形如：

```json
{ "law_name": "中华人民共和国民法典", "article_no": "第六百七十条" }
```

**这里刻意不写条文内容。** 把记忆里"差不多是这句"的表述当作权威文本喂给模型，
是法律 AI 最危险的失败模式：检索层给出的引用本身就是编造的，
后面的推理再严密也只是把错误包装得更可信。

## 2. 引用如何变成"已核验"

```
规则/模型给出 (法规名, 条号)
   → citation.resolve_citations() 回 legal_provisions 比对
      ├─ 命中且 is_sample=False  → verified=true   ✅ 可作为结论依据
      ├─ 命中但 is_sample=True   → verified=false  ⚠️ "原文未导入" → 强制人工复核
      └─ 查不到                  → verified=false  ⚠️ "知识库未收录" → 强制人工复核
```

也就是说：**在导入权威原文之前，系统不会产出任何"已核验"的结论。**
这是设计上的刻意行为，不是缺陷。

## 3. 导入权威原文的正确流程

1. 从官方渠道取原文：全国人大网（npc.gov.cn）、司法部、中国政府网、
   国家金融监督管理总局、最高人民法院发布的司法解释正式文本；
2. 逐条录入，`content` 必须是官方文本，不得由人工转述或让模型补全；
3. 填写 `effective_on` / `repealed_on` / `version_label` / `source_url`；
4. 导入接口会自动向量化（配置真实 Embedding 时）：

```bash
curl -X POST http://localhost:8000/api/v1/knowledge/provisions \
  -H "Content-Type: application/json" \
  -d '{
    "law_name": "中华人民共和国民法典",
    "article_no": "第六百七十条",
    "content": "借款的利息不得预先在本金中扣除。利息预先在本金中扣除的，应当按照实际借款数额返还借款并计算利息。",
    "doc_type": "law",
    "effective_on": "2021-01-01",
    "source_url": "http://www.npc.gov.cn/..."
  }'
```

也可在「法规知识库」页面左侧列表点击"填入表单"，逐条补齐占位登记。

## 4. 阈值口径需要谁来维护

`Settings` 里的这几个值属于**需要定期人工确认的业务参数**：

| 参数 | 含义 | 更新节奏 |
| --- | --- | --- |
| `LPR_ONE_YEAR_RATE` | 一年期贷款市场报价利率 | 每月 20 日前后（全国银行间同业拆借中心公布） |
| `LPR_MULTIPLE` | 司法保护上限倍数（4 倍） | 跟随司法解释修订 |
| `REGULATORY_COST_CEILING` | 消费金融/小贷综合成本红线 | 跟随监管窗口指导与新规 |
| `CONFIDENCE_ROUTING_THRESHOLD` | 转人工的置信度阈值 | 依据复核队列的误报率/调级率调整 |

要点：**4×LPR 适用于民间借贷，持牌金融机构贷款不适用该上限**；
对持牌机构更相关的是综合融资成本的监管口径。两类规则在内置库中通过
`applies_to` 分别绑定合同种类，选择错误的规则集会得出错误结论，
因此报告页必须展示当前阈值口径（前端已实现）。

## 5. 监管公开信息的采集边界

`app/services/ingestion/regulator.py` 提供的是**带合规护栏的采集框架**：

- 默认关闭（`INGESTION_ENABLED=false`）；
- 抓取前检查 `robots.txt`，取不到 robots 时按保守策略拒绝；
- 强制自定义 UA 与最小请求间隔；
- 接口要求显式传 `confirmed_compliance_ok=true`，把"已核对使用条款"的责任交给调用方；
- 内置来源的 `implemented=false`，选择器需按目标站点**当前版面**人工核对后才允许执行；
- 解析不出条目时返回错误而不是空结果，避免"看起来采集成功但其实没数据"。

罚单可用于"同类违规已被处罚"的类比论证，但**罚单本身不是法律依据**：
结论引用只能落在 `legal_provisions` 的条文上。

## 6. 使用免责

- 系统输出为**辅助性合规提示**，不构成法律意见，不得直接替代法务与外部律师审查；
- 高风险、引用未核验、原文定位失败的结论必须经法务确认后对外使用；
- 离线模式（Mock LLM / Mock 向量）下产出的结果只能用于链路验证；
  健康检查、界面顶栏与报告摘要都会显式标注当前降级状态；
- 上传的合同文件属敏感商业资料：落盘文件按 UUID 寻址、目录已 gitignore，
  生产部署需另行处理加密、留存期限与访问审计。
